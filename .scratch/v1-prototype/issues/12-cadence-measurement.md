# 12: วัด cadence จากเซ็นเซอร์ระหว่างวิ่ง

**Blocked by:** 11

**Status:** done — ดูหมายเหตุเรื่อง AC1 ก่อน โดยเฉพาะถ้าจะพูดเรื่องนี้ตอนนำเสนอ

## What to build

ระหว่างวิ่ง แอปอ่าน accelerometer แล้วคำนวณ cadence เป็นก้าวต่อนาที แสดงสดบนหน้าวิ่ง

ต้องเก็บ cadence เป็นชุดตัวอย่างตลอด Session ไม่ใช่เก็บค่าเดียวตอนจบ เพราะ FormScore ต้องรู้ว่ามันตกตอนไหนของการวิ่ง

การอ่านเซ็นเซอร์ต้องไม่ทำให้แอปกระตุกหรือกินแบตจนผิดปกติ และต้องหยุดอ่านเมื่อผู้ใช้กดหยุดชั่วคราว

## Acceptance criteria

- [x] ⚠️ cadence แสดงสดระหว่างวิ่ง **แต่ใกล้เคียงการนับด้วยมือแค่ต่ำกว่า ~150 ก้าว/นาที** จังหวะวิ่งจริงทั่วไป (160-190) จะต่ำกว่าจริงเสมอ — ดูหมายเหตุ ข้อจำกัดทางฟิสิกส์ ไม่ใช่บั๊ก
- [x] cadence ถูกเก็บเป็นชุดตัวอย่างตลอดการวิ่ง ไม่ใช่ค่าเดียว
- [x] หยุดอ่านเซ็นเซอร์เมื่อกดหยุดชั่วคราวและกลับมาอ่านต่อเมื่อวิ่งต่อ
- [x] แอปไม่กระตุกขณะอ่านเซ็นเซอร์ (ยืนยันด้วยเหตุผลเชิงวิศวกรรม อัปเดตสถานะเฉพาะตอนตรวจพบก้าวใหม่ ไม่ใช่ทุกตัวอย่าง 200ms — ยังไม่เคยวัดจริงบนเครื่อง)
- [x] จัดการกรณีเครื่องไม่มีเซ็นเซอร์โดยไม่ทำให้แอปพัง (`Accelerometer.isAvailableAsync()` + fallback ถ้า promise reject ด้วย)

## หมายเหตุ

### ⚠️ ข้อค้นพบสำคัญ: เพดานอัตราสุ่มตัวอย่างของแอนดรอยด์ทำให้ cadence วัดจังหวะวิ่งจริงไม่แม่น

Android 12 ขึ้นไปบังคับเพดานอัตราสุ่มตัวอย่าง accelerometer ไว้ที่ 200ms (5Hz) เสมอ ไม่ว่าแอปจะขอถี่
กว่านั้นแค่ไหน ยืนยันจากข้อความดิบในเอกสารทางการของ expo-sensors SDK 54 โดยตรง (ไม่ใช่แค่สรุปจาก AI
เพราะรอบแรกที่ลองสรุปได้ตัวเลขผิดเป็น "200Hz" ต้องเปิดหน้าเว็บอ่านข้อความจริงเองอีกรอบถึงยืนยันได้ว่า
"200ms" ถูกต้อง): "Starting from Android 12 (API level 31), the system has a 200ms limit for each
sensor updates." ที่ 5Hz ความถี่ไนควิสต์คือ 2.5Hz = 150 ก้าว/นาทีพอดี ตามทฤษฎีการสุ่มตัวอย่างของ
Nyquist-Shannon จังหวะวิ่งทั่วไป (160-190 ก้าว/นาที) **เกินขีดจำกัดนี้เสมอ** และยิ่งจังหวะเร็วยิ่งถูก
วัดต่ำกว่าจริงมากขึ้น (ยืนยันด้วยสัญญาณสังเคราะห์: 140 spm กู้คืนแม่นเกือบเป๊ะ, 170 spm ต่ำกว่าจริง
อย่างน้อย 15%, 190 spm ต่ำกว่าจริงอย่างน้อย 25% — ดูเทสต์ใน services/step-detector.test.ts)

**นี่ไม่ใช่บั๊กที่แก้ด้วยการจูนอัลกอริทึมได้** เป็นขีดจำกัดทางคณิตศาสตร์ของการสุ่มตัวอย่าง ลองจูน
threshold แล้วพบว่าปรับให้ต่ำกว่า 150 spm แม่นขึ้นได้จริง (140 spm: 123.5→140.0 พอดี) โดยไม่มีผลเสียที่
190 spm เลย (ยังคงต่ำกว่าจริงเท่าเดิมไม่ว่าจะจูนยังไง) — นำค่าที่จูนแล้วมาใช้เป็นค่าเริ่มต้นแล้ว แต่
ไม่มีทางแก้ให้ครอบคลุมจังหวะวิ่งจริงทั่วไปได้ด้วยวิธีนี้

เพิ่มสิทธิ์ `HIGH_SAMPLING_RATE_SENSORS` ใน app.json ไว้เผื่อแล้ว (จะยกเพดานนี้ได้ถ้ามีผล) **แต่แทบ
ไม่น่าจะมีผลใน Expo Go** เพราะสิทธิ์ระดับแอนดรอยด์แบบนี้ต้องคอมไพล์ native manifest ใหม่ ซึ่ง Expo Go
เป็นเชลล์สำเร็จรูปที่คอมไพล์ไว้ล่วงหน้าแล้ว (ดู ADR 0002) ทางเดียวที่จะรู้ผลจริงคือทำ development
build ซึ่งขัดกับ ADR 0002 ที่ตัดสินใจไว้แล้วว่าจะไม่ทำในโปรเจกต์นี้

**ผลกระทบต่อการนำเสนอ**: ถ้าจะโชว์ cadence สดตอนวิ่งจริงบนเวที ตัวเลขที่เห็นจะต่ำกว่าจังหวะจริงถ้า
วิ่งเร็วกว่าเดินเร็ว ๆ ควรพูดถึงเป็น "ค่าประมาณ" ตรง ๆ (มี label "(ประมาณ)" กำกับไว้ในแอปแล้ว) ไม่ควร
อ้างว่าแม่นยำระดับนับด้วยมือ ยังไม่เคยทดสอบกับเครื่องแอนดรอยด์จริงเลยในสภาพแวดล้อมนี้ ตัวเลขทั้งหมด
มาจากสัญญาณสังเคราะห์เท่านั้น ควรทดสอบซ้ำกับเครื่องจริงก่อนวันนำเสนอถ้าเป็นไปได้

ผลกระทบต่อฟีเจอร์ในอนาคต: FormScore (ตั๋ว 06) ตั้งสมมติฐานว่า cadence เป็นสัญญาณที่วัดแม่น ไม่จริง
อีกต่อไปสำหรับจังหวะวิ่งทั่วไป และความไม่สมมาตรของการวัดต่ำกว่าจริง (ยิ่งเร็วยิ่งตกมากกว่า) เสี่ยงกลบ
สัญญาณ cadenceDropped จริงตอนเชื่อมข้อมูลเข้าด้วยกันในตั๋ว 13 — เพิ่มหมายเหตุไว้ในทั้งสองตั๋วแล้ว
เพิ่มหมายเหตุใน [ADR 0002](../../../docs/adr/0002-stay-in-expo-go-for-the-whole-project.md) แล้วด้วย

### บั๊กจริงที่เจอและแก้ระหว่างรีวิว

- **เซนเซอร์ยังอ่านต่อหลังกด "จบการวิ่ง" ถ้าไม่กดหยุดชั่วคราวก่อน** — `useLiveRunTracker.finish()`
  ไม่ได้เปลี่ยน `status` ออกจาก `'running'` ทำให้ `isRunning` ยังเป็น true ต่อบนหน้าจอสรุป เซนเซอร์เลย
  ยังทำงานเบื้องหลังกินแบตต่อโดยไม่จำเป็น แก้โดยเช็ค `!finished` เพิ่มในเงื่อนไข active ของ
  useCadenceSensor ที่ app/live-run.tsx (จุดเดียวกันนี้ทำให้ KeepAwake ก็รั่วแบบเดียวกันด้วย แต่เป็น
  โค้ดจากตั๋ว 11 ที่รีวิวผ่านไปแล้ว ไม่ได้แก้ในตั๋วนี้ แค่บันทึกไว้ให้เห็น)
- **ใช้ `Date.now()` แทน timestamp จริงของเซนเซอร์** — เพิ่ม jitter จาก JS bridge เข้าไปโดยไม่จำเป็นบน
  สัญญาณที่ตึงมืออยู่แล้ว แก้โดยใช้ฟิลด์ `timestamp` ของ AccelerometerMeasurement เอง (หน่วยวินาที
  แปลงเป็น ms) แทน
- **`Accelerometer.isAvailableAsync()` ไม่มี `.catch`** — ถ้า promise reject แทนที่จะ resolve เป็น
  false จะค้างที่สถานะ 'checking' ตลอดไป ไม่ถึงกับพัง แต่เพิ่ม `.catch` ให้ตกไปที่ 'unavailable' แทน
