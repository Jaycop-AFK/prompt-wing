# 14: ประวัติการวิ่งรายสัปดาห์รายเดือนรายปี

**Blocked by:** 13

**Status:** done

## What to build

ผู้ใช้เปิดดูประวัติการวิ่งได้ สลับมุมมองระหว่างรายสัปดาห์ รายเดือน และรายปี เห็นกราฟแท่งระยะทางในแต่ละวัน ระยะรวมของช่วงนั้น และเทียบกับเป้าหมาย

กดที่รายการแต่ละครั้งแล้วเปิดดูหน้าสรุปของการวิ่งครั้งนั้นซ้ำได้

มีมุมมองแนวโน้มของ FormScore ย้อนหลัง เพื่อให้ผู้ใช้เห็นว่าฟอร์มดีขึ้นหรือแย่ลง

## Acceptance criteria

- [x] สลับมุมมองรายสัปดาห์ รายเดือน รายปีได้ (ปุ่มแรกใช้ชื่อ "7 วันล่าสุด" ไม่ใช่ "สัปดาห์นี้" ดูหมายเหตุ)
- [x] กราฟแท่งแสดงระยะทางแต่ละวันถูกต้องตามข้อมูลที่บันทึกไว้ (รายปีเป็นแท่งละเดือน ดูหมายเหตุ)
- [x] กดรายการแล้วเปิดหน้าสรุปของครั้งนั้นได้ (ใช้จอ run-summary ตัวเดียวกับตอนเพิ่งวิ่งจบ)
- [x] แสดงแนวโน้ม FormScore ย้อนหลัง (ลำดับจุดสี ไม่ใช่กราฟเส้น ดูหมายเหตุ)
- [x] กรณียังไม่มีประวัติเลย แสดงสถานะว่างที่บอกผู้ใช้ว่าต้องทำอะไรต่อ พร้อมปุ่มไปหน้าวิ่ง

## หมายเหตุ (ปิดตั๋ว)

### สิ่งที่เบี่ยงจากตัวอักษรของตั๋ว

- **"รายสัปดาห์" ทำเป็นหน้าต่างเลื่อนเจ็ดวันล่าสุด ไม่ใช่สัปดาห์ตามปฏิทิน** ถ้าเริ่มนับวันจันทร์
  ผู้ใช้ที่เปิดดูเช้าวันจันทร์จะเห็นกราฟเกือบว่างทั้งที่เพิ่งวิ่งมาทั้งสัปดาห์ แต่รีวิวทั้งสองแกนชี้ตรงกัน
  ว่าถ้าทำแบบนี้แล้วยังใช้ป้ายว่า "สัปดาห์นี้" คือโกหกผู้ใช้ เพราะวางอยู่ข้าง "เดือนนี้" กับ "ปีนี้"
  ที่อิงปฏิทินจริงทั้งคู่ เลยเปลี่ยนป้ายเป็น **"7 วันล่าสุด"** ให้ตรงกับสิ่งที่โค้ดทำจริง
- **มุมมองรายปีเป็นแท่งละเดือน ไม่ใช่แท่งละวัน** ตามตัวอักษรของ AC ควรเป็นรายวัน แต่ 365 แท่งบน
  จอมือถืออ่านไม่ได้เลย และตัดเดือนที่ยังมาไม่ถึงออกด้วย ไม่งั้นครึ่งกราฟเป็นแท่งว่างของอนาคต
  ซึ่งดูเหมือนผู้ใช้ขาดซ้อมทั้งที่ยังไม่ถึงเวลา
- **แนวโน้ม FormScore เป็นลำดับจุดสี ไม่ใช่กราฟเส้น** เพราะ CONTEXT.md นิยาม FormScore เป็น
  ประโยคกับธงบอกว่าอะไรตก ไม่ใช่ตัวเลข การประดิษฐ์คะแนน 0-100 ขึ้นมาเพื่อวาดเส้นจะขัดกับนิยาม
  ในโดเมนโดยตรง และสร้างความแม่นยำปลอมที่ข้อมูลจริงไม่รองรับ มีคำอธิบายสีกำกับไว้ใต้จุดเสมอ

### เป้าหมายในหน้านี้ยังไม่ใช่ของผู้ใช้จริง

ตั๋ว 09 (โปรไฟล์) ยังไม่เสร็จ จึงยังไม่มีที่เก็บเป้าหมายระยะยาวที่ผู้ใช้เลือกเอง หน้านี้เลยใช้ค่าเริ่มต้น
"สุขภาพ" (3 กม./วัน) ไปก่อน **และคูณด้วยทุกวันในช่วง ซึ่งเท่ากับสมมติว่าวิ่งทุกวันไม่มีวันพัก**
ทั้งที่ core/coach/daily-goal.ts บันทึกไว้เองว่าเป้าหมายสุขภาพที่ตั้งใจจริงคือสามวันต่อสัปดาห์
ตัวเลขเป้าหมายในหน้านี้จึงสูงกว่าที่ควรเป็นประมาณสองเท่า เขียนกำกับไว้บนจอตรง ๆ ทั้งสองข้อแล้ว
(ทั้งเรื่องค่าเริ่มต้นและเรื่องสมมติว่าวิ่งทุกวัน) ต้องแก้ให้ถูกจริงเมื่อตั๋ว 09 เสร็จ

### บั๊กจริงที่เจอและแก้ระหว่างรีวิว

- **บั๊กเขตเวลาที่มีการปรับเวลาตามฤดูกาล สองจุด** ทั้ง `start` และ `end` ของช่วงเคยคำนวณด้วยการ
  บวกลบมิลลิวินาที ทั้งที่คอมเมนต์ในไฟล์เดียวกันเตือนตัวเองไว้แล้วว่าห้ามทำ ผลคือ (1) ในสัปดาห์ที่
  คร่อมวันปรับเวลา ทุกแท่งจะเลื่อนไปอยู่ที่ 23:00 ของวันก่อนหน้า ไม่ตรงกับวันของ Session สักอัน
  กราฟว่างทั้งแผงเงียบ ๆ ทั้งที่ยอดรวมกับรายการด้านล่างยังถูก และ (2) วันที่ยาว 25 ชั่วโมง การวิ่งที่จบ
  หลัง 23:00 จะหลุดออกจากทุกช่วงไปเลย ทั้งยอดรวม กราฟ และรายการ แก้โดยสร้างทุกจุดตัดด้วย
  ตัวสร้าง Date เสมอ
- **จุดสีของแนวโน้มฟอร์มไม่มีคำอธิบาย** ผู้ใช้เห็นจุดสีเรียงกันโดยไม่รู้ว่าสีไหนแปลว่าอะไร เพิ่ม
  คำอธิบายสีแล้ว โดยแยก `components/ui/legend.tsx` ออกมาจาก app/weather.tsx ที่มีอยู่แล้ว
- **จุดสีอ่านด้วยโปรแกรมอ่านหน้าจอไม่ได้** ใส่ accessibilityLabel ไว้บน View เปล่าซึ่งไม่ประกาศตัวเอง
  เป็นองค์ประกอบที่เข้าถึงได้ ต้องใส่ accessible ด้วย ไม่งั้นข้อมูลที่สื่อด้วยสีล้วนหายไปทั้งหมด
- **ชื่อฟิลด์ `targetDistanceKm` ชนกับ SessionTarget** CONTEXT.md จองคำว่า target ไว้ให้
  "เป้าหมายรอบนี้" แล้ว ส่วนตัวเลขนี้มาจาก DailyGoal คนละเรื่องกัน เปลี่ยนเป็น `goalDistanceKm`
- **การ์ดแนวโน้มไม่เปลี่ยนตามช่วงที่เลือก** ตั้งใจให้ดู 10 ครั้งล่าสุดเสมอ (ช่วงสั้น ๆ อาจมีการวิ่ง
  ครั้งเดียวซึ่งดูแนวโน้มไม่ได้) แต่เดิมไม่ได้บอกผู้ใช้ เลยดูเหมือนการ์ดค้าง เขียนกำกับหัวข้อแล้ว
- **จอ error กลืนข้อมูลที่ยังดีอยู่และไม่มีทางกู้คืน** เพิ่มปุ่มลองใหม่ และบอกตรง ๆ ว่าข้อมูลที่บันทึก
  ไปแล้วยังอยู่ครบ

### ข้อจำกัดของการทดสอบที่ต้องรู้

เขียนเทสต์สำหรับบั๊กเขตเวลาไว้แล้ว **แต่มันไม่ได้พิสูจน์อะไรบนเครื่องที่พัฒนาอยู่นี้** ตรวจสอบแล้วว่า
Node บนวินโดวส์ไม่สนใจตัวแปรแวดล้อม TZ เลย (Intl ยังรายงาน Asia/Bangkok อยู่ดี) และยืนยันด้วยการ
ใส่บั๊กกลับเข้าไปแล้วรันใหม่ ปรากฏว่าเทสต์ผ่านหมดเหมือนเดิม เก็บเทสต์ไว้เพราะจะจับได้จริงถ้าวันหนึ่ง
รันบน CI หรือเครื่องที่ตั้งเขตเวลาแบบมี DST ส่วนความถูกต้องของโค้ดจริงมาจากการไม่บวกลบมิลลิวินาที
กับขอบเขตของวันเลย ซึ่งถูกต้องโดยตัวมันเองไม่ว่าเขตเวลาไหน ไม่ได้อ้างว่าเทสต์เป็นหลักฐาน

ทั้งจอนี้ยังไม่เคยรันบนเครื่องจริง ตรวจด้วย typecheck + เทสต์ (203 ผ่าน) + lint + bundle-compile เท่านั้น
