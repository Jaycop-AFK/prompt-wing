# 13: สรุปการวิ่ง คะแนนฟอร์ม และบันทึกลงเครื่อง

**Blocked by:** 06, 12

**Status:** ready-for-agent

## What to build

ผู้ใช้กดจบการวิ่งแล้วเห็นหน้าสรุปที่มีระยะทาง เวลา pace เฉลี่ย แคลอรี สถิติแยกรายกิโลเมตร แผนที่เส้นทางที่วิ่ง และ FormScore เป็นประโยคที่บอกว่าฟอร์มเป็นยังไงและควรทำอะไรต่อ

Session ถูกบันทึกลงเครื่องด้วย expo-sqlite ทันทีที่จบ และเปิดดูซ้ำได้แม้ปิดแอปไปแล้วหรือไม่มีอินเทอร์เน็ต ดู ADR 0003

การเขียนลงเครื่องต้องเกิดก่อนเสมอ ไม่มีอะไรในแอปนี้ที่ต้องรอเน็ตถึงจะบันทึกได้

## Acceptance criteria

- [ ] หน้าสรุปแสดงระยะทาง เวลา pace แคลอรี และ splits รายกิโลเมตร
- [ ] แสดง FormScore เป็นประโยคที่บอกสิ่งที่ควรทำต่อ
- [ ] แสดงแผนที่เส้นทางที่วิ่งมา
- [ ] Session ถูกบันทึกลงเครื่องและเปิดดูซ้ำได้หลังปิดเปิดแอป
- [ ] บันทึกสำเร็จแม้ปิดอินเทอร์เน็ต
- [ ] Session ที่สั้นเกินไปแสดงว่าข้อมูลไม่พอสำหรับประเมินฟอร์ม

## หมายเหตุ (เพิ่มระหว่างตั๋ว 12)

ตั๋ว 12 พบว่า cadence จาก accelerometer บนแอนดรอยด์ 12 ขึ้นไปถูกวัดต่ำกว่าจริงเสมอที่จังหวะวิ่งทั่วไป
(160-190 ก้าว/นาที) และยิ่งจังหวะเร็วยิ่งถูกกดต่ำกว่าจริงมากขึ้น (ขีดจำกัด Nyquist ของอัตราสุ่มตัวอย่าง
200ms ที่ระบบบังคับ ดู services/step-detector.ts) ก่อนเชื่อม `hooks/use-cadence-sensor.ts`'s `samples`
เข้ากับ `evaluateFormScore` (ตั๋ว 06) ต้องคิดว่าความไม่สมมาตรนี้จะกลบสัญญาณ cadenceDropped จริงหรือไม่
เช่น วิ่งจริงจาก 190 ตกเหลือ 170 ช่วงท้าย อาจวัดได้ออกมาใกล้เคียงกันเพราะทั้งคู่โดนกดต่ำกว่าจริงคนละ
ระดับ ยังไม่มีทางแก้ที่ชัดเจนในตอนนี้ อาจต้องแจ้งผู้ใช้ตรง ๆ ว่า cadence เป็นค่าประมาณ หรือลดน้ำหนัก
สัญญาณนี้ลงเมื่อคำนวณ FormScore แทนที่จะเชื่อว่าแม่นเท่าที่ตั๋ว 06 ตั้งใจไว้แต่แรก
