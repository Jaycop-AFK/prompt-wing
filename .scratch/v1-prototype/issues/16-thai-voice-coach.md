# 16: โค้ชเสียงภาษาไทยระหว่างวิ่ง

**Blocked by:** 11

**Status:** done

## What to build

ระหว่างวิ่ง ผู้ใช้ได้ยินเสียงภาษาไทยบอกเมื่อ pace เร็วหรือช้ากว่าที่แนะนำ และบอกทุกครั้งที่วิ่งครบหนึ่งกิโลเมตร ทำให้ไม่ต้องหยิบมือถือขึ้นมาดู

ใช้ expo-speech ซึ่งอยู่ใน Expo Go และรองรับภาษาไทย ไม่ต้องต่อบริการภายนอกและไม่มีค่าใช้จ่าย

ผู้ใช้ต้องปิดเสียงโค้ชได้ และเสียงต้องไม่พูดถี่จนน่ารำคาญ ต้องมีระยะห่างขั้นต่ำระหว่างการพูดแต่ละครั้ง

## Acceptance criteria

- [x] ได้ยินเสียงไทยเตือนเมื่อ pace หลุดจากช่วงที่แนะนำ (เทียบกับ pace แนะนำเดียวกับที่โชว์ก่อนวิ่ง)
- [x] ได้ยินเสียงไทยบอกทุกครั้งที่ครบหนึ่งกิโลเมตร
- [x] ปิดเสียงโค้ชได้และค่าที่เลือกยังอยู่ครั้งถัดไป (ไอคอนลำโพงที่หัวจอวิ่ง ผูก AsyncStorage)
- [x] เสียงไม่พูดซ้อนกันและไม่พูดถี่เกินไป
- [x] จัดการกรณีเครื่องไม่มีเสียงภาษาไทยติดตั้งโดยไม่ทำให้แอปพัง

## หมายเหตุ (ปิดตั๋ว)

### บั๊กจริงที่เจอเอง ก่อนถึงขั้นรีวิว

**หยุดชั่วคราวแล้ววิ่งต่อจะประกาศกิโลเมตรที่ผ่านไปแล้วซ้ำ** เขียน effect ไว้รีเซ็ตตัวนับกิโลเมตร/
เวลาคูลดาวน์ทุกครั้งที่ `isRunning` เป็น false โดยตั้งใจให้ครอบคลุมแค่ตอนยังไม่เริ่มวิ่ง แต่ `isRunning`
เป็น false ตอนหยุดชั่วคราวด้วยเหมือนกัน ทำให้หยุดแล้ววิ่งต่อจะรีเซ็ตตัวนับทุกครั้ง กิโลเมตรที่ประกาศ
ไปแล้วก่อนหยุดจะถูกประกาศซ้ำอีกรอบ พบระหว่างไล่ทวนโค้ดเองก่อนส่งรีวิว แก้ด้วยการลบ effect นั้นทิ้งไป
เฉย ๆ เพราะจอนี้ navigate ออกเสมอตอนจบการวิ่งจริง (ดู handleFinish ใน live-run.tsx) ค่าเริ่มต้น 0
จาก useRef ก็เพียงพออยู่แล้วสำหรับการวิ่งรอบใหม่โดยไม่ต้องมี effect รีเซ็ตเพิ่ม

### บั๊กจริงที่เจอและแก้ระหว่างรีวิวสองแกน

- **กิโลเมตรที่ครบพอดีอาจไม่ถูกประกาศเลยตลอดกาล ไม่ใช่แค่ช้าไป** (พบโดยฝั่ง spec) `speak()` ข้าม
  การพูดเงียบ ๆ ถ้ากำลังพูดประโยคอื่นค้างอยู่ แต่ตัวนับ `lastAnnouncedKmRef`/`lastPaceNudgeAtRef`
  เดิมถูกขยับทันทีโดยไม่รอผลว่าพูดสำเร็จจริงไหม ถ้ากิโลเมตรใหม่มาถึงตอนกำลังพูดคำเตือน pace ค้างอยู่
  พอดี กิโลเมตรนั้นจะถูกข้ามไปโดยไม่เคยพูดเลยสักครั้ง แล้ว `nextKmMilestone` จะไม่เสนอกิโลเมตรนั้นซ้ำ
  อีกต่อไปเพราะถือว่าผ่านไปแล้ว ขัดกับคำว่า "ทุกครั้ง" ตรง ๆ แก้โดยให้ `speak()` คืนค่า boolean บอกว่า
  เพิ่งเริ่มพูดจริงหรือถูกข้าม แล้วขยับตัวนับเฉพาะตอนได้ true กลับมาเท่านั้น ตอนนี้กิโลเมตรที่พลาดจะถูก
  เสนอซ้ำในรอบถัดไปแทนที่จะหายไปเงียบ ๆ
- **เขียนผลข้างเคียงไว้ในฟังก์ชัน updater ของ setState** (พบโดยฝั่ง standards) `toggle()` เดิมเรียก
  `AsyncStorage.setItem` และ `Speech.stop()` อยู่ข้างในฟังก์ชันที่ส่งให้ `setEnabled` เป็นบั๊กชนิด
  เดียวกับที่แก้ไปแล้วในตั๋ว 09 (hooks/use-profile.tsx) เพราะ React เรียกฟังก์ชัน updater ซ้ำได้ใน
  StrictMode หรือรอบเรนเดอร์ที่ถูกทิ้ง แก้โดยคำนวณค่าใหม่จาก `enabled` ที่ปิดล้อมไว้แทน แล้วค่อยเรียก
  ผลข้างเคียงเป็นคำสั่งธรรมดาหลัง `setEnabled` แยกออกมาต่างหาก
- **โหลดค่าที่บันทึกไว้จากเครื่องอาจทับสิ่งที่ผู้ใช้เพิ่งกดสลับไป** รูปแบบเดียวกับที่แก้ไว้ในตั๋ว 09/15
  เพิ่ม `editCount` ref กันการโหลดที่มาทีหลังทับค่าที่ผู้ใช้เพิ่งกดไปแล้ว พร้อมเพิ่ม `cancelled` guard
  กัน setState หลัง unmount ให้ตรงกับรูปแบบของ hooks/use-theme.tsx และ hooks/use-profile.tsx
- **ไม่มีทางกู้คืนถ้าเอนจินเสียงพูดไม่เรียก callback กลับมาเลย** ถ้า `onDone`/`onStopped`/`onError`
  ไม่ถูกเรียกเลยสักตัว (ปัญหาที่เป็นไปได้ของเอนจินบางรุ่น ไม่ใช่พฤติกรรมที่เอกสารรับประกัน) `isSpeakingRef`
  จะค้างเป็น true ตลอดไปและโค้ชจะเงียบไปตลอดการวิ่งที่เหลือ เพิ่มตัวจับเวลา watchdog 8 วินาทีบังคับล้าง
  ค่าทิ้งถ้าไม่มี callback ไหนตอบกลับมาในเวลานั้น
- **คอมเมนต์อ้างเกินจริงว่า try/catch จัดการกรณีไม่มีเสียงไทย** ความจริงคือ expo-speech เลือกเสียงสำรอง
  ให้เองโดยไม่ throw อยู่แล้วเมื่อไม่มีเสียงภาษาไทยติดตั้ง (ยืนยันจากซอร์สจริงของ native module ทั้ง
  แอนดรอยด์และ iOS) try/catch ในโค้ดป้องกันเฉพาะกรณีเรียกเข้าโมดูลเสียงพูดไม่สำเร็จตั้งแต่ต้นเท่านั้น
  (เช่นไม่มีเอนจินเสียงพูดเลย) แก้คอมเมนต์ให้ตรงกับสิ่งที่โค้ดป้องกันจริง ไม่ใช่สิ่งที่ AC ขอ
- แก้ import ของ `PaceDriftLevel` ให้ผ่าน barrel `@/core/coach` แทนการ import ตรงจากไฟล์ย่อย ให้ตรง
  กับที่ทุกจุดอื่นในโปรเจกต์ทำ

### ดุลพินิจที่เลือกเอง ไม่ได้มาจากมาตรฐานไหน

pace ที่ใช้ตัดสินว่าหลุดช่วงคือ pace เฉลี่ยสะสมตั้งแต่เริ่มวิ่ง ตัวเดียวกับที่แสดงบนจอ ไม่ใช่ pace
ช่วงล่าสุด เพื่อให้สิ่งที่โค้ชพูดตรงกับตัวเลขที่ผู้ใช้เห็นเสมอ ข้อเสียคือช่วงท้ายการวิ่งยาวค่าเฉลี่ยจะนิ่ง
ขึ้นเรื่อย ๆ ตอบสนองต่อ pace ที่เปลี่ยนช้าลง ขอบเขตที่ถือว่า "หลุดช่วง" (±30 วินาที/กม.) คูลดาวน์คำเตือน
pace (60 วินาที) และเวลา watchdog (8 วินาที) เป็นตัวเลขที่เลือกเอาเองทั้งหมด ปรับได้จากค่าคงที่ในไฟล์
core/coach/voice-coach.ts และ hooks/use-voice-coach.ts ถ้าทดสอบจริงแล้วรู้สึกถี่หรือห่างเกินไป

ปุ่มปิดเสียงโค้ชอยู่ที่หัวจอวิ่งจริงเท่านั้น ไม่ได้ซ้ำไว้ที่จอตั้งเป้าหมายก่อนวิ่งหรือหน้าเพิ่มเติมของ
ตั๋ว 18 (ยังไม่ถูกสร้าง) เพราะ AC ขอแค่ว่าต้องปิดได้และค่าที่เลือกจำไว้ ไม่ได้ระบุตำแหน่ง

### ยังไม่เคยรันบนเครื่องจริง

เสียงพูดจริง จังหวะพูด ความเป็นธรรมชาติของเสียงไทยที่เครื่องเลือกให้ และพฤติกรรมตอนไม่มีเสียงไทย
ติดตั้งจริง ยังไม่เคยได้ยินเลยในสภาพแวดล้อมนี้ ตรวจสอบแล้วด้วย typecheck + เทสต์ (295 ผ่าน) + lint
+ bundle-compile และการอ่านซอร์สจริงของ native module expo-speech ทั้งแอนดรอยด์และ iOS เท่านั้น
