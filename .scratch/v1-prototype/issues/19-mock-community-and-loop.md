# 19: แท็บชุมชนและสร้างเส้นทางวงกลมแบบจำลอง

**Blocked by:** 15

**Status:** done

## What to build

ผู้ใช้เปิดแท็บชุมชนแล้วเห็นปฏิทินงานวิ่งไทยที่ดูวันที่ ระยะทาง จังหวัด และค่าสมัครได้ และเห็นหน้าหาเพื่อนวิ่งที่จับคู่คนที่วิ่งสวนเดียวกัน เวลาใกล้กัน pace ใกล้กัน

ในแท็บที่วิ่งมีปุ่มสร้างเส้นทางวงกลม ผู้ใช้ระบุระยะที่ต้องการแล้วเห็น Route วงกลมกลับมาที่จุดเดิมวาดบนแผนที่

ทั้งสามอย่างนี้ใช้ข้อมูลจำลองทั้งหมด ไม่มีตรรกะจริงอยู่เบื้องหลัง ทุกจอต้องมีป้ายกำกับชัดเจนว่าเป็นภาพจำลอง เพื่อให้ตอนนำเสนออธิบายได้ตรงไปตรงมาว่าส่วนไหนทำงานจริงและส่วนไหนยังไม่ทำ

การยืนยันตัวตนสำหรับหาเพื่อนวิ่งอยู่นอกขอบเขต แสดงเป็นป้ายสถานะเท่านั้น

## Acceptance criteria

- [x] ปฏิทินงานวิ่งแสดงรายการงานพร้อมวันที่ ระยะทาง จังหวัด และค่าสมัคร
- [x] หน้าหาเพื่อนวิ่งแสดงรายการคนที่จับคู่ได้พร้อม pace และเวลาที่วิ่ง
- [x] สร้างเส้นทางวงกลมตามระยะที่ระบุแล้วเห็นเส้นวาดบนแผนที่
- [x] ทุกจอในตั๋วนี้มีป้ายกำกับว่าเป็นข้อมูลจำลอง
- [x] ไม่มีจอไหนพังหรือค้างเมื่อกดเข้าไปดู

## หมายเหตุ (ปิดตั๋ว)

### เรขาคณิตของเส้นทางวงกลม

`services/route-generator.ts` คำนวณวงกลมล้วน ๆ ไม่ใช่เส้นทางจริงตามถนน (ตามที่ตั๋วกำหนดว่าไม่มีตรรกะ
จริง) รัศมีคำนวณย้อนกลับจาก `distanceKm / (2π)` ทำให้เส้นรอบวงของวงกลมอุดมคติเท่ากับระยะที่ขอเป๊ะ
ทางพีชคณิต จุดเริ่มต้นอยู่บนเส้นรอบวงพอดี (ไม่ใช่จุดศูนย์กลาง) เพื่อให้ผู้ใช้เห็นเส้นทางเริ่ม-จบที่
ตำแหน่งจริงของตัวเองสมชื่อ "กลับมาที่จุดเดิม" ยืนยันด้วยเทสต์ 5 ตัวรวมถึงตรวจระยะรอบวงจริง (บวก
ความยาวคอร์ดทุกช่วง) เทียบกับระยะที่ขอ

### บั๊กจริงที่เจอและแก้ระหว่างรีวิวสองแกน

- **แผนที่ไม่ขยับตามขนาดเส้นทางที่เลือก** (พบโดยฝั่ง standards) เดิมใช้ `MAP_DELTA` ค่าคงที่ตายตัว
  ทำให้ 4 ใน 6 ตัวเลือกระยะ (8/10/15/21 กม.) วาดเส้นทางส่วนใหญ่ออกนอกกรอบที่มองเห็นตั้งแต่เปิดจอ
  มา ผู้ใช้จะเห็นแค่เสี้ยวเดียวของวงกลมเหมือนแอปวาดผิด ทั้งที่จริงคำนวณถูกแล้วแค่กล้องไม่ได้ซูมให้พอดี
  แก้ด้วย `MapView.fitToCoordinates` ผูกกับ `onMapReady` (ครั้งแรกที่ยัง mount) และเรียกเองตรง ๆ ใน
  `handleGenerate` (ครั้งถัดไปที่แผนที่พร้อมอยู่แล้ว เพราะ onMapReady ยิงแค่ครั้งเดียวไม่ยิงซ้ำ)
- **ปุ่มสร้างเส้นทางไม่มีสถานะกำลังโหลดเลย** (พบโดยฝั่ง spec) `getCurrentCoordinates` ไม่ throw จริง
  แต่ `getCurrentPositionAsync` บนเครื่องจริงอาจใช้เวลาหลายวินาทีเมื่อสัญญาณ GPS อ่อน กดปุ่มแล้วไม่มี
  อะไรตอบสนองเลยจะดูเหมือนจอค้าง ทั้งที่ `hooks/use-venues.ts` มีสถานะโหลดให้ฟังก์ชันเดียวกันนี้อยู่
  แล้ว แก้ด้วยการเพิ่ม `isGenerating` ปิดปุ่ม+เปลี่ยนข้อความระหว่างรอ พร้อมปิดชิปเลือกระยะไปด้วยกันไม่ให้
  กดเปลี่ยนระยะระหว่างที่คำขอเดิมยังค้างอยู่ (ไม่งั้นเส้นทางที่ได้อาจไม่ตรงกับชิปที่ไฮไลต์อยู่ตอนเสร็จ)
- แก้คอมเมนต์สองจุดที่ผิดพลาดเรื่องตัวเลข (ทิศทางวนจริงคือทวนเข็มนาฬิกาไม่ใช่ตามเข็ม และคลาดเคลื่อน
  ที่ 36 จุดคือประมาณ 0.13% ไม่ใช่ต่ำกว่า 0.1%) ไม่กระทบพฤติกรรมจริงเลย แค่คอมเมนต์เขียนตัวเลขผิด

### เก็บทำความสะอาด

ลบ `components/ui/coming-soon.tsx` เพราะตั๋วนี้แทนที่ placeholder สองจุดสุดท้าย (แท็บที่วิ่งกับแท็บ
ชุมชน) ที่เหลืออยู่ในทั้ง repo ไม่มีที่ใช้เหลือแล้ว (จุดแรกถูกแทนที่ไปแล้วตอนตั๋ว 18)

### ดุลพินิจที่เลือกเอง

ชื่องานวิ่งและชื่อคนหาเพื่อนวิ่งในข้อมูลจำลองเป็นชื่อที่ตั้งขึ้นเองทั้งหมด ไม่ใช่งานหรือบัญชีจริง
วันที่งานวิ่งทุกงานตั้งเป็นอนาคตเทียบกับวันที่ปัจจุบันของเซสชันนี้ (30 ส.ค. 2569) เพื่อไม่ให้ดูเหมือน
งานที่ผ่านไปแล้วตอนสาธิต ระยะที่เลือกได้ในตัวสร้างเส้นทางเป็นชิปคงที่ 6 ค่า (3/5/8/10/15/21 กม.) ไม่มี
ช่องกรอกตัวเลขอิสระ เพราะ AC ไม่ได้ขอความยืดหยุ่นระดับนั้นและชิปตัดปัญหาค่าติดลบ/ศูนย์ไปได้ทั้งหมด

### ยังไม่เคยรันบนเครื่องจริง

การเคลื่อนกล้องของ `fitToCoordinates` ตอนสร้างเส้นทางใหม่ทับของเดิม และรูปทรงวงกลมบนแผนที่จริง
ยังไม่เคยเห็นด้วยตาในสภาพแวดล้อมนี้ ตรวจสอบแล้วด้วย typecheck + เทสต์ (305 ผ่าน) + lint +
bundle-compile และการตรวจสอบ API ของ `react-native-maps` จาก type declaration จริงที่ติดตั้งไว้เท่านั้น
