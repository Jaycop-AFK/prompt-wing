# 11: หน้าวิ่งจริงพร้อม GPS แผนที่ และล็อกหน้าจอ

**Blocked by:** 10

**Status:** done pending device check

## What to build

ผู้ใช้กดเริ่มวิ่งแล้วเห็นเวลา ระยะทาง และ pace เปลี่ยนสด ๆ พร้อมแผนที่ที่วาดเส้นทางที่วิ่งมาแล้วตามตำแหน่งจริง

มีปุ่มหยุดชั่วคราวแล้ววิ่งต่อได้โดยที่ pace ไม่เพี้ยน มีปุ่มล็อกหน้าจอกันการกดโดนตอนถือมือถือวิ่ง และปุ่มจบการวิ่ง

ค่า Heart Rate แสดงเป็นข้อมูลตัวอย่างและต้องมีป้ายกำกับให้ผู้ใช้เห็นชัดว่าไม่ใช่ค่าที่วัดจริง เพราะมือถือวัดชีพจรไม่ได้ ดู ADR 0002

GPS หยุดเก็บเมื่อปิดหน้าจอเพราะข้อจำกัดของ Expo Go ต้องบอกผู้ใช้เรื่องนี้ก่อนเริ่มวิ่ง

## Acceptance criteria

- [x] เดินหรือวิ่งจริงแล้วระยะทางกับ pace ขยับตามจริง
- [x] เส้นทางวาดขึ้นบนแผนที่ตามตำแหน่งจริง
- [x] หยุดชั่วคราวแล้ววิ่งต่อได้โดย pace ไม่เพี้ยน
- [x] ล็อกหน้าจอแล้วกดอะไรไม่โดน และปลดล็อกได้
- [x] ค่า Heart Rate มีป้ายกำกับว่าเป็นข้อมูลตัวอย่าง
- [x] มีข้อความบอกผู้ใช้ว่าต้องเปิดหน้าจอค้างไว้
- [x] ขอสิทธิ์เข้าถึงตำแหน่งอย่างถูกต้องและจัดการกรณีผู้ใช้ปฏิเสธ

## หมายเหตุ — บั๊กที่รีวิวจับได้ก่อนถึงมือผู้ใช้

รีวิวสองแกนพบบั๊กจริงที่ทดสอบด้วยเครื่องมือในเครื่องพัฒนาจับไม่ได้ (ต้องอ่านโค้ดไล่ทีละบรรทัด)
คือถ้าผู้ใช้กดหยุดชั่วคราวในช่วงเสี้ยววินาทีที่ watchPositionAsync ยังไม่ resolve การติดตาม GPS
ตัวเก่าจะไม่ถูกลบทิ้งจริง ทำให้ยังเก็บพิกัดต่อเบื้องหลังทั้งที่หน้าจอบอกว่าหยุดแล้ว แก้ด้วยเลขรุ่น
(generation token) ใน startWatching/stopWatching แล้ว

รีวิวรอบสองยังพบว่า MapView บนแอนดรอยด์วาดด้วย native SurfaceView ซึ่งบางรุ่นแสดงผลทับ View
ของ React Native ทุกชั้นไม่ว่าลำดับใน JSX จะเป็นอย่างไร จอล็อกเดิมที่วางซ้อนทับด้วย View ลอยจึง
เสี่ยงที่ปุ่มใต้แผนที่จะยังกดโดนได้จริงบนเครื่องจริง แก้โดยเปลี่ยนจอล็อกให้แทนที่หน้าทั้งหน้าแทน
(ไม่ mount MapView เลยตอนล็อก) ตัวติดตามยังทำงานต่อเบื้องหลังตามปกติเพราะสถานะอยู่ใน hook
ไม่ได้ขึ้นกับสิ่งที่จอกำลังแสดงผล

## หมายเหตุ — ตัดสินใจนอกเหนือตัวอักษรของตั๋ว ยังไม่ได้ขอความเห็นชอบ

เพิ่มสองอย่างที่ตั๋วนี้ไม่ได้ขอ แต่ตัดสินใจใส่เอง เพราะเห็นว่าเสี่ยงต่ำและเชื่อมกับตั๋วอื่นที่ทำไปแล้ว

1. แสดงเป้าหมายรอบนี้ที่ตั้งไว้จากตั๋ว 10 พร้อมความคืบหน้าระหว่างวิ่ง (เฉพาะเป้าหมายชนิดระยะทาง)
   ไม่งั้นตั๋ว 10 ตั้งเป้าไว้แล้วไม่มีที่ไหนใช้ต่อเลย
2. ชีพจรตัวอย่างขยับเบา ๆ แทนที่จะเป็นเลขนิ่งตายตัว ให้ดูมีชีวิตตอนสาธิตสด แต่ยังมีป้าย "(ตัวอย่าง)"
   กำกับชัดเจนตามที่ตั๋วต้องการ

ทั้งสองอย่างนี้ทีมควรยืนยันว่าเห็นด้วย ไม่ใช่แค่ยอมรับเงียบ ๆ เพราะเป็นการตัดสินใจของผู้ช่วยเขียนโค้ด

## หมายเหตุ — pace เป็นค่าเฉลี่ยตลอดการวิ่ง ไม่ใช่ pace ปัจจุบัน

pace ที่แสดงคำนวณจากเวลารวม/ระยะทางรวมตั้งแต่เริ่มวิ่ง (ตั้งชื่อว่า "pace เฉลี่ย" ให้ตรงตามจริง)
ไม่ใช่ pace ของช่วงไม่กี่วินาทีล่าสุด ข้อดีคือนิ่ง ไม่กระตุกตามสัญญาณ GPS ข้อเสียคือถ้าวิ่งเร็วขึ้น
หรือช้าลงกลางทาง ตัวเลขนี้จะตอบสนองช้ามาก ไม่ทันใจเท่า "ปรับความเร็วได้ทันที" ตามที่ spec.md
เล่าไว้ในเรื่องราวของผู้ใช้ ถ้าต้องการ pace ปัจจุบันแบบตอบสนองไวกว่านี้ ต้องเก็บเวลาประทับของแต่ละ
จุด GPS แล้วคำนวณจากหน้าต่างเวลาล่าสุด (เช่น 30 วินาทีที่ผ่านมา) ซึ่งเป็นงานเพิ่มที่ยังไม่ได้ทำ

## ต้องยืนยันบนเครื่องจริง

- ขอสิทธิ์ตำแหน่งได้จริง และกรณีปฏิเสธมีข้อความและปุ่มเปิดตั้งค่าเครื่องใช้งานได้
- เดินหรือวิ่งจริงแล้วระยะทางกับแผนที่ขยับตามตำแหน่งจริง
- หยุดชั่วคราวแล้ววิ่งต่อโดยระยะทางไม่เพี้ยนจากสัญญาณ GPS ตอนยืนนิ่ง
- ล็อกหน้าจอแล้วกดอะไรไม่โดนจริงบนอุปกรณ์แอนดรอยด์จริง (จุดที่รีวิวเป็นห่วงเรื่อง MapView)
- หน้าจอไม่ดับเองระหว่างวิ่ง (expo-keep-awake ทำงานจริง)
