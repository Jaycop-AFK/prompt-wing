# 15: ที่วิ่งจาก OpenStreetMap พร้อมข้อมูลที่กรอกเอง

**Blocked by:** 01

**Status:** done

## What to build

ผู้ใช้เปิดแท็บที่วิ่งแล้วเห็น Venue ใกล้ตัวทั้งบนแผนที่และเป็นรายการ สลับสองมุมมองได้ เรียงตามระยะใกล้ ความนิยม หรือที่บันทึกไว้ กดเข้าไปดูรายละเอียดแล้วเห็นสิ่งอำนวยความสะดวกห้าอย่างคือห้องน้ำ ที่จอดรถ ไฟส่องสว่าง จุดน้ำดื่ม และร้านค้า พร้อมปุ่มนำทาง

ข้อมูลมาสองชั้น ชั้นครอบคลุมยิง Overpass สดตามตำแหน่งผู้ใช้ซึ่งฟรีและใช้ได้ทุกจังหวัด ชั้นละเอียดเป็นไฟล์ที่กรอกเองสำหรับที่วิ่งรอบ มจพ ปราจีนบุรี ทับข้อมูลจาก Overpass ด้วยการจับคู่พิกัด

จากการสำรวจจริงพบว่าสี่ในเก้าแห่งรอบปราจีนบุรีไม่มีแม้แต่ชื่อใน OSM และไม่มีแห่งไหนมีข้อมูลสิ่งอำนวยความสะดวกเลย Venue ที่ไม่มีชื่อต้องแสดงเป็นประเภทของมันแทน ห้ามปล่อยว่าง และข้อมูลที่ไม่มีต้องแสดงว่าไม่ทราบ ไม่ใช่แสดงว่าไม่มี

ตัวเลขบนการ์ดต้องมีคำกำกับเสมอ ห่างจากคุณ กับ ลู่วิ่งยาว เป็นคนละความหมายและห้ามแสดงเป็นตัวเลขเปล่า

## หมายเหตุ (ปิดตั๋ว)

### เรื่อง "การสำรวจจริง" ของเก้าแห่งรอบปราจีนบุรี — ทำไม่ได้ตามตัวอักษร

ตั๋วอ้างถึงการสำรวจภาคสนามจริงเก้าแห่ง แต่เขียนโค้ดในสภาพแวดล้อมนี้ไม่มีทางไปเดินสำรวจสถานที่จริงได้
แทนที่จะเดา ได้ยิง Overpass API จริงตรงพิกัด มจพ. ปราจีนบุรี ระหว่างพัฒนา (ไม่ใช่แค่ทดสอบด้วย mock)
พบว่า:

- มี way ชื่อ "อาคารศูนย์กีฬาเฉลิมพระเกียรติ" อยู่จริงที่พิกัดเดียวกับที่ตั้งมหาวิทยาลัยพอดี (ห่างไม่ถึง
  10 เมตร) ยืนยันตรงกับหน้าเว็บทางการของ มจพ. ที่ระบุว่ามีศูนย์กีฬาพร้อมสนามฟุตบอลหญ้าเทียม บาสเกตบอล
  แบดมินตัน เทนนิส และฟิตเนส — คือ**มีชื่ออยู่แล้วใน OSM** ไม่ได้อยู่ในกลุ่มที่ไม่มีชื่อตามที่ตั๋วอ้างถึง
  งานของข้อมูลที่กรอกเองสำหรับแห่งนี้จึงคือเสริมสิ่งอำนวยความสะดวก ไม่ใช่เติมชื่อที่หายไป
- พบสนามกีฬาอีกสามแห่งในรัศมีเดียวกันที่ไม่มีชื่อจริง (ฟุตบอล ฟุตซอล เทนนิส) ตรงกับที่ตั๋วอธิบายไว้
  แห่งเหล่านี้ไม่ต้องเติมในไฟล์ข้อมูลที่กรอกเอง เพราะจะปรากฏเองจาก Overpass สดพร้อมแสดงประเภทแทนชื่อ
  โดยอัตโนมัติอยู่แล้ว เป็นข้อมูลจริง ไม่ต้องปลอมตัวอย่างซ้อนเข้าไปให้ผู้ชมนำเสนอเห็น
- ไม่มีแห่งไหนเลยมีข้อมูลสิ่งอำนวยความสะดวกใน OSM ตรงกับที่ตั๋วอธิบายไว้เป๊ะ

จึงตัดสินใจให้ `services/curated-venues.ts` มีแค่รายการเดียว (ศูนย์กีฬา มจพ.) ที่ยืนยันได้จริงจากสอง
แหล่ง แทนที่จะเติมข้อมูลสมมติอีกแปดแห่งซึ่งจะเป็นการโกหกผู้ชมตอนนำเสนอ สิ่งอำนวยความสะดวกที่ทำ
เครื่องหมาย "มี" มีแค่ห้องน้ำกับที่จอดรถ (อ้างอิงจากสามัญสำนึกของศูนย์กีฬามหาวิทยาลัยที่มีเจ้าหน้าที่
ประจำ) ไฟส่องสว่าง จุดน้ำดื่ม ร้านค้า ทำเครื่องหมายไม่ทราบเพราะไม่มีแหล่งยืนยัน ก่อนใช้งานจริงควรให้
คนที่อยู่พื้นที่จริงตรวจสอบซ้ำโดยเฉพาะสามช่องนี้ และเพิ่มที่วิ่งอื่นที่รู้จักจริงเข้าไปในไฟล์เดียวกันได้เลย

### บั๊กจริงที่เจอระหว่างพัฒนา (ก่อนรีวิว)

**Overpass ปฏิเสธคำขอด้วย 406 Not Acceptable ถ้าไม่ส่ง header Accept กับ User-Agent เอง** พบจากการ
ยิง API จริงตรง ๆ ไม่ใช่แค่เดาจากเอกสาร ถ้าไม่แก้ ฟีเจอร์ทั้งตั๋วจะพังเงียบทุกครั้งจริงบนอุปกรณ์จริง
ไม่ใช่แค่บางกรณี เพราะ fetch ของ JS ไม่ใส่สอง header นี้ให้เป็นค่าเริ่มต้น แก้แล้วใน services/overpass.ts

### บั๊กจริงที่เจอและแก้ระหว่างรีวิว

- **Venue ที่กรอกเองอาจถูกจับคู่ซ้ำกับ Overpass หลายชิ้น** ถ้า Overpass คืนสองชิ้นที่อยู่ใกล้ Venue
  ที่กรอกเองแห่งเดียวกัน (เช่น node กับ way ของสถานที่เดียวกัน) ข้อมูลกรอกเองจะถูกก็อปทับทั้งสองชิ้น
  กลายเป็นการ์ด/หมุดซ้ำ แก้ให้จับคู่ได้แค่ครั้งเดียวต่อ Venue กรอกเองหนึ่งแห่ง
- **Venue ที่กรอกเองโผล่ในรายการของผู้ใช้ทุกจังหวัดทั่วประเทศ** เพราะ Overpass มีตัวกรองระยะในตัว
  แต่ข้อมูลกรอกเองเป็นรายการคงที่ไม่ถูกจำกัดระยะ ขัดกับคำว่า "รอบตัว...ใช้ได้ทุกจังหวัด" ที่ตั๋วสัญญาไว้
  แก้ด้วยการกรองข้อมูลกรอกเองด้วยระยะค้นหาเดียวกับ Overpass ก่อนรวมเสมอ
- **รายการที่บันทึกไว้เสี่ยงถูกทับด้วยค่าเก่าจากเครื่อง** ถ้าผู้ใช้กดบันทึกระหว่างที่ยังโหลดค่าเดิมจาก
  AsyncStorage ไม่เสร็จ เป็นบั๊กชนิดเดียวกับที่แก้ไปแล้วในตั๋ว 09 (hooks/use-profile.tsx) แก้แบบเดียวกัน
- **ป้ายคำว่า "สถานที่นี้" หลุดมาในข้อความหนึ่งจุด** CONTEXT.md ห้ามใช้ "สถานที่" แทน Venue แก้เป็น
  "ที่วิ่งนี้" แล้ว
- **ความนิยมเป็นข้อมูลจำลองแต่ไม่มีป้ายกำกับให้ผู้ใช้เห็นเลย** ทั้งที่คอมเมนต์ในโค้ดเขียนไว้เองว่าต้องมี
  เพิ่มป้าย MockBadge ที่มีอยู่แล้วในแอป (`components/ui/mock-badge.tsx`) ให้ขึ้นเมื่อเลือกเรียงตามนี้
- **ระยะที่ปัดเป็นเมตรพอดี 1000 แสดงเป็น "1000 ม." แทนที่จะเป็น "1.0 กม."** เกิดจากเทียบค่าดิบกับ 1
  กม.ก่อนปัด ไม่ใช่ปัดก่อนแล้วค่อยตัดสินหน่วย แก้แล้วพร้อมเทสต์ปิดกรณีขอบเขตนี้ไว้

### ยังไม่เคยรันบนเครื่องจริง

MapView, Marker, และปุ่มนำทางด้วย geo: URI ยังไม่เคยทดสอบบนอุปกรณ์จริงเลยในสภาพแวดล้อมนี้ ตรวจสอบ
แล้วด้วย typecheck + เทสต์ (279 ผ่าน) + lint + bundle-compile และการยิง Overpass API จริงเท่านั้น
ความยาวลู่วิ่ง (loopLengthKm) ยังไม่มีแหล่งไหนให้ค่าจริงเลยสักที่ (ต้องคำนวณจากรูปทรงเต็มของเส้นทาง
ซึ่งต้องขอ `out geom` แทน `out center` และรับมือ way ที่ไม่ใช่วงปิดจริงด้วย เกินขอบเขตของตั๋วนี้) จึง
ยังไม่เคยเห็น "ลู่วิ่งยาว" ขึ้นจริงบนจอเลยสักครั้ง แม้กลไกแสดงผลจะพร้อมและมีเทสต์รองรับแล้วก็ตาม
