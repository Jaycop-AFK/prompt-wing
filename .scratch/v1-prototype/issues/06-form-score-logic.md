# 06: ตรรกะคะแนนฟอร์มการวิ่ง

**Blocked by:** 02

**Status:** done

## What to build

เพิ่มฟังก์ชันในโมดูลตัวตัดสินใจที่รับชุดตัวอย่าง cadence และ pace ตลอด Session แล้วคืน FormScore

ใช้สามสัญญาณที่มือถือวัดได้แม่นจริงเท่านั้น คือ cadence โดยรวม cadence ที่ตกลงในช่วงท้าย และ pace ที่ตกลงในช่วงท้าย ห้ามใช้ ground contact time หรือความสมมาตรซ้ายขวาเพราะมือถือในกระเป๋าวัดไม่ได้แม่นพอ

ผลลัพธ์ต้องเป็นประโยคภาษาไทยที่บอกให้ผู้ใช้ทำอะไรต่อได้ ไม่ใช่ตัวเลขลอย ๆ ตัวอย่างเช่นบอกว่า cadence ตกจากเท่าไหร่เป็นเท่าไหร่ในกิโลสุดท้าย และนั่นแปลว่าเริ่มลงส้นซึ่งเสี่ยงเจ็บหน้าแข้ง

Session ที่สั้นเกินกว่าจะสรุปอะไรได้ต้องบอกตรง ๆ ว่าข้อมูลไม่พอ ห้ามเดา

## Acceptance criteria

- [x] cadence ที่คงที่ตลอดไม่ถูกตัดสินว่าฟอร์มเสีย มีเทสต์ยืนยัน
- [x] cadence ที่ตกช่วงท้ายถูกจับได้ มีเทสต์ยืนยัน
- [x] pace ที่ตกช่วงท้ายถูกจับได้ มีเทสต์ยืนยัน
- [x] Session ที่สั้นเกินไปคืนผลว่าข้อมูลไม่พอ มีเทสต์ยืนยัน
- [x] ผลลัพธ์มีประโยคภาษาไทยที่บอกสิ่งที่ควรทำต่อเสมอ

## หมายเหตุ (เพิ่มทีหลังจากตั๋ว 12)

บรรทัด 11 ระบุว่า cadence เป็นสัญญาณที่ "มือถือวัดได้แม่นจริง" ข้อสมมติฐานนี้ไม่จริงอีกต่อไปสำหรับ
จังหวะวิ่งทั่วไป (160-190 ก้าว/นาที) บนเครื่องแอนดรอยด์ 12 ขึ้นไป — ตั๋ว 12 ยืนยันด้วยเทสต์สังเคราะห์
ว่า accelerometer ถูกเพดานอัตราสุ่มตัวอย่างของระบบปฏิบัติการไว้ที่ 200ms (5Hz) เสมอ ทำให้จังหวะช่วงนี้
ถูกวัดต่ำกว่าจริงเสมอตามขีดจำกัดของ Nyquist ไม่ใช่ปัญหาการวัดที่แก้ด้วยการจูนได้ (รายละเอียดเต็มใน
services/step-detector.ts)

ตรรกะในไฟล์นี้เอง (การเทียบ cadence ต้นกับท้าย Session) ยังถูกต้องอยู่ ถ้าป้อนตัวเลขที่แม่นเข้าไป
แต่ตัวเลขจริงที่ตั๋ว 13 จะป้อนเข้ามาจากเซนเซอร์จริงจะไม่แม่นในลักษณะที่ไม่สมมาตร (จังหวะเร็วถูกกดต่ำ
กว่าจังหวะช้ามากกว่า) ซึ่งอาจกลบสัญญาณ cadenceDropped จริงแทนที่จะขยายให้เห็นชัดขึ้น ดูหมายเหตุใน
ตั๋ว 13 ก่อนเริ่มเชื่อมข้อมูลจริงเข้ากับฟังก์ชันนี้
