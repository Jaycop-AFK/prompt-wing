# พร้อมวิ่ง — Prototype v1

Status: ready-for-agent

## Problem Statement

นักวิ่งชาวไทยอายุ 25–40 ปี เจอปัญหาสามอย่างที่แอปวิ่งที่มีอยู่ในตลาดไม่แก้ให้เลย

**หนึ่ง — ไม่รู้ว่าวันนี้ควรวิ่งหรือไม่ควรวิ่ง** เมืองไทยร้อนจัดและมี PM2.5 หนักตามฤดู แอปอย่าง Strava หรือ Nike Run Club ไม่พูดถึงเรื่องนี้เลยสักคำ ส่วนแอปอากาศอย่าง Air4Thai หรือ IQAir บอกตัวเลขได้ แต่ไม่ผูกกับแผนวิ่งของผู้ใช้ ผลคือผู้ใช้ต้องเปิดสองสามแอปแล้วตีความตัวเลขเอง ซึ่งคนส่วนใหญ่ตีความไม่เป็น และสุดท้ายก็ออกไปวิ่งตอนเก้าโมงเช้าในวันที่ดัชนีความร้อนแตะ 41 องศา

**สอง — ฟอร์มการวิ่งพังโดยไม่รู้ตัวจนบาดเจ็บ** อาการเจ็บน่องและหน้าแข้งเกิดจากฟอร์มที่เสียตอนล้า ผู้ใช้รู้ตัวอีกทีตอนเจ็บแล้ว แอปที่มีอยู่บันทึกระยะทางกับเวลา แต่ไม่บอกว่าฟอร์มเสียตรงไหน และท่าวอร์มอัพที่แอปทั่วไปให้มาเป็นรายการตายตัวชุดเดียวใช้ทุกวัน ไม่สนว่าวันนี้อากาศเป็นยังไงหรือครั้งก่อนวิ่งแล้วเป็นยังไง

**สาม — วิ่งตอนเย็นแล้วมืดกลางทาง** คนทำงานวิ่งได้ช่วงเย็นเป็นหลัก แต่ไม่มีแอปไหนเตือนว่าอีกกี่นาทีฟ้าจะมืด หรือว่าที่ที่กำลังจะไปมีไฟส่องสว่างหรือเปล่า

## Solution

แอปมือถือภาษาไทยชื่อ **พร้อมวิ่ง** ที่พาผู้ใช้ผ่านหนึ่งรอบของการวิ่งตั้งแต่ต้นจนจบ โดยตอบสามปัญหาข้างต้นในจังหวะที่ผู้ใช้ต้องการคำตอบพอดี

เปิดแอปมาเจอ **ใบอนุญาตวิ่งวันนี้** เป็นคำตัดสินสีเขียว เหลือง หรือแดง พร้อมประโยคเดียวที่บอกว่าควรวิ่งช่วงไหน ไม่ใช่ตัวเลขให้ตีความเอง ถ้าเป็นสีเหลือง ระบบลด `SessionTarget` ให้อัตโนมัติพร้อมบอกเหตุผล

ก่อนวิ่งกด **วอร์มอัพ** แล้วได้ `WarmUpSet` ที่ระบบเลือกมาให้สำหรับวันนี้โดยเฉพาะ ไม่ใช่รายการตายตัว มีตัวละครเวกเตอร์ทำท่าให้ดูสดพร้อมนับถอยหลัง

ระหว่างวิ่งเห็นแผนที่และตัวเลขสด พร้อมโค้ชเสียงภาษาไทยคอยบอกเมื่อ pace หลุด

จบแล้วได้ **คะแนนฟอร์มการวิ่ง** เป็นประโยคที่บอกว่าเกิดอะไรขึ้นกับฟอร์มและควรทำอะไรต่อ แล้วคะแนนนั้นย้อนกลับไปเปลี่ยน `WarmUpSet` ของครั้งถัดไป ทำให้วงจรปิดสมบูรณ์

## User Stories

### ใบอนุญาตวิ่งวันนี้

1. As a นักวิ่ง, I want เห็นคำตัดสินสีเขียว เหลือง หรือแดงทันทีที่เปิดแอป, so that ผมตัดสินใจได้ในสามวินาทีว่าวันนี้จะออกไปวิ่งไหมโดยไม่ต้องตีความตัวเลขเอง
2. As a นักวิ่ง, I want รู้ว่าอะไรเป็นตัวที่ทำให้วันนี้ไม่เขียว, so that ผมเข้าใจว่าเป็นเพราะร้อนหรือเพราะฝุ่น และตัดสินใจต่างกันได้
3. As a นักวิ่ง, I want เห็น `ClearWindow` เป็นประโยคเดียวว่าวันนี้วิ่งได้ช่วงไหน, so that ผมวางแผนวันได้โดยไม่ต้องไล่ดูพยากรณ์รายชั่วโมงทั้งวัน
4. As a นักวิ่ง, I want เห็นแถบเวลาทั้งวันเป็นสีเขียวเหลืองแดง, so that ผมเห็นภาพรวมว่าช่วงไหนของวันดีที่สุด
5. As a นักวิ่ง, I want รู้ว่าค่า PM2.5 มาจากสถานีไหนและห่างจากผมกี่กิโลเมตร, so that ผมประเมินได้เองว่าตัวเลขนี้น่าเชื่อถือแค่ไหนสำหรับที่ที่ผมอยู่
6. As a นักวิ่ง, I want ให้แอปบอกตรง ๆ เมื่อสถานีตรวจวัดใกล้ตัวไม่ส่งข้อมูล, so that ผมไม่เข้าใจผิดว่าอากาศดีทั้งที่จริง ๆ คือไม่มีข้อมูล
7. As a นักวิ่ง, I want ให้ระบบลด `SessionTarget` ให้อัตโนมัติเมื่อใบอนุญาตเป็นสีเหลือง, so that ผมไม่ฝืนซ้อมหนักในวันที่ร่างกายรับภาระเพิ่มจากอากาศอยู่แล้ว
8. As a นักวิ่ง, I want เห็นเหตุผลกำกับทุกครั้งที่ระบบลดเป้าหมายให้, so that ผมเชื่อถือคำแนะนำแทนที่จะรู้สึกว่าแอปตัดสินใจแทนผมมั่ว ๆ
9. As a นักวิ่ง, I want เห็นเวลาพระอาทิตย์ตกของวันนี้, so that ผมรู้ว่าเหลือเวลากลางวันอีกเท่าไหร่
10. As a นักวิ่ง, I want ถูกเตือนเมื่อเวลาที่เหลือก่อนฟ้ามืดน้อยกว่าเวลาที่ผมน่าจะใช้วิ่งจนจบ, so that ผมไม่ติดอยู่กลางทางตอนมืด

### วอร์มอัพ

11. As a นักวิ่ง, I want ได้ `WarmUpSet` ที่เลือกมาให้สำหรับวันนี้โดยเฉพาะ, so that ผมไม่ต้องทำท่าเดิมห้าท่าทุกวันโดยไม่รู้ว่าเหมาะกับวันนี้ไหม
12. As a นักวิ่ง, I want ให้ชุดท่าเปลี่ยนตามอากาศวันนี้, so that วันที่ร้อนจัดผมไม่ต้องทำท่ากระโดดที่ทำให้ร่างกายร้อนเกินไปก่อนออกวิ่ง
13. As a นักวิ่ง, I want ให้ชุดท่าเปลี่ยนตามฟอร์มการวิ่งครั้งก่อน, so that ถ้าครั้งก่อน cadence ตกช่วงท้าย ผมจะได้ท่าน่องและหน้าแข้งเพิ่ม
14. As a นักวิ่ง, I want ให้ชุดท่าเปลี่ยนตาม `SessionTarget` ของวันนี้, so that วันที่จะวิ่งไกลผมได้วอร์มนานกว่าวันที่วิ่งสั้น
15. As a นักวิ่ง, I want เลือกได้ว่าจะวอร์ม 5, 10 หรือ 15 นาที, so that ผมวอร์มได้แม้ในวันที่มีเวลาน้อย
16. As a นักวิ่ง, I want เห็นตัวละครทำท่าให้ดูสด ๆ ไม่ใช่ภาพนิ่ง, so that ผมทำตามได้ถูกต้องโดยไม่ต้องเดาว่าท่าเคลื่อนไหวยังไง
17. As a นักวิ่ง, I want แยกออกว่าตัวละครกำลังใช้ขาข้างไหน, so that ผมทำตามได้ถูกข้างจริง ๆ
18. As a นักวิ่ง, I want เห็นว่ากล้ามเนื้อมัดไหนกำลังถูกยืดอยู่, so that ผมเข้าใจว่าท่านี้มีไว้ทำอะไรและทำให้ถูกจุด
19. As a นักวิ่ง, I want เห็นนาฬิกานับถอยหลังของแต่ละท่า, so that ผมรู้ว่าต้องค้างท่านี้อีกนานแค่ไหน
20. As a นักวิ่ง, I want รู้สึกการสั่นเตือนตอนเปลี่ยนท่า, so that ผมไม่ต้องจ้องหน้าจอตลอดเวลาที่วอร์ม
21. As a นักวิ่ง, I want ข้ามท่าที่ทำไม่ได้, so that ผมยังวอร์มต่อได้แม้บางท่าจะไม่เหมาะกับผม
22. As a นักวิ่ง, I want ให้ทุกชุดวอร์มอัพครบทั้งสี่ขั้นของ RAMP เสมอ, so that ผมได้วอร์มที่ถูกหลักสากลไม่ใช่แค่ท่ายืดกองรวมกัน

### การวิ่ง

23. As a นักวิ่ง, I want ตั้ง `SessionTarget` เป็นระยะทาง เวลา หรือแคลอรี, so that ผมกำหนดเป้าหมายได้ตรงกับสิ่งที่ผมสนใจในวันนั้น
24. As a นักวิ่ง, I want เห็นสรุปก่อนเริ่มวิ่งว่าน่าจะใช้เวลาเท่าไหร่และเผาผลาญเท่าไหร่, so that ผมเตรียมตัวและวางแผนเวลาได้
25. As a นักวิ่ง, I want เห็นเวลา ระยะทาง และ pace เปลี่ยนสด ๆ ระหว่างวิ่ง, so that ผมปรับความเร็วได้ทันที
26. As a นักวิ่ง, I want เห็นเส้นทางที่ผมวิ่งวาดขึ้นบนแผนที่ระหว่างวิ่ง, so that ผมรู้ว่าผมอยู่ตรงไหนและวิ่งมาทางไหนแล้ว
27. As a นักวิ่ง, I want ล็อกหน้าจอได้, so that ผมไม่กดโดนอะไรตอนถือมือถือวิ่ง
28. As a นักวิ่ง, I want หยุดชั่วคราวแล้ววิ่งต่อได้, so that ผมหยุดรอข้ามถนนได้โดยที่ pace ไม่เพี้ยน
29. As a นักวิ่ง, I want ได้ยินโค้ชเสียงภาษาไทยบอกเมื่อ pace เร็วหรือช้าเกิน, so that ผมแก้ได้โดยไม่ต้องหยิบมือถือขึ้นมาดู
30. As a นักวิ่ง, I want ได้ยินเสียงบอกเมื่อวิ่งครบแต่ละกิโลเมตร, so that ผมรู้ความคืบหน้าโดยไม่ต้องดูจอ
31. As a นักวิ่ง, I want ปิดเสียงโค้ชได้, so that ผมฟังเพลงหรือวิ่งเงียบ ๆ ได้ตามต้องการ
32. As a นักวิ่ง, I want เห็นว่าค่า Heart Rate เป็นข้อมูลตัวอย่าง, so that ผมไม่เข้าใจผิดว่ามือถือวัดชีพจรผมได้จริง

### คะแนนฟอร์มการวิ่ง

33. As a นักวิ่ง, I want เห็น `FormScore` เป็นประโยคที่อ่านรู้เรื่อง ไม่ใช่ตัวเลขลอย ๆ, so that ผมรู้ว่าต้องแก้อะไรจริง ๆ
34. As a นักวิ่ง, I want รู้ว่า cadence ของผมตกลงตอนไหนของการวิ่ง, so that ผมเข้าใจว่าฟอร์มผมเริ่มพังตรงจุดไหน
35. As a นักวิ่ง, I want รู้ว่า pace ของผมตกลงช่วงท้ายมากแค่ไหน, so that ผมรู้ว่าผมออกตัวเร็วเกินไปหรือเปล่า
36. As a นักวิ่ง, I want เห็นความเชื่อมโยงระหว่างฟอร์มที่เสียกับความเสี่ยงบาดเจ็บ, so that ผมมีเหตุผลที่จะแก้ไขมันจริง ๆ
37. As a นักวิ่ง, I want เห็นสถิติแยกรายกิโลเมตร, so that ผมดูได้ว่าผมคุมความเร็วสม่ำเสมอแค่ไหน
38. As a นักวิ่ง, I want ดู `FormScore` ย้อนหลังได้, so that ผมเห็นว่าฟอร์มผมดีขึ้นหรือแย่ลงเมื่อเวลาผ่านไป

41. As a นักวิ่ง, I want เห็นสิ่งอำนวยความสะดวกของแต่ละ `Venue`, so that ผมรู้ว่ามีห้องน้ำ ที่จอดรถ ไฟส่องสว่าง จุดน้ำดื่ม และร้านค้าหรือไม่
42. As a นักวิ่ง, I want รู้ว่า `Venue` ไหนมีไฟส่องสว่าง, so that ผมเลือกที่วิ่งตอนเย็นได้อย่างปลอดภัย
43. As a นักวิ่ง, I want เรียง `Venue` ตามระยะใกล้ ความนิยม หรือที่บันทึกไว้, so that ผมหาที่วิ่งที่ต้องการได้เร็ว

56. As a ผู้นำเสนองาน, I want ให้ทุกจอที่ยังใช้ข้อมูลจำลองมีป้ายกำกับชัดเจน, so that ผมอธิบายได้ตรงไปตรงมาว่าส่วนไหนทำงานจริงและส่วนไหนเป็นภาพจำลอง

## Implementation Decisions

### ข้อจำกัดที่กำหนดทุกอย่าง

ดู ADR 0002 — ทุกไลบรารีต้องรันใน Expo Go ของ SDK 54 ได้ ไม่มี development build ผลคือใช้ `react-native-maps` ไม่ใช่ `expo-maps`, GPS หยุดเมื่อปิดหน้าจอ, เชื่อมนาฬิกาหรือแอปสุขภาพไม่ได้ และ Heart Rate เป็นข้อมูลจำลองถาวรที่ต้องมีป้ายกำกับ

### โมดูล `ตัวตัดสินใจ` (the coach) — seam เดียวของโปรเจกต์

ฟังก์ชันบริสุทธิ์สี่ตัว ไม่ import อะไรจาก React Native เลย รับข้อมูลดิบเข้า คืนข้อมูลดิบออก เวลาปัจจุบันส่งเข้าไปเป็นพารามิเตอร์เสมอ ห้ามเรียกนาฬิกาข้างใน

- `ประเมินใบอนุญาตวิ่ง` — รับค่าอากาศและอากาศเสียรายชั่วโมง 24 ชั่วโมง เวลาพระอาทิตย์ตก และเวลาปัจจุบัน คืน `RunClearance` กับ `ClearWindow`
- `เลือกชุดวอร์มอัพ` — รับ `RunClearance`, `FormScore` ครั้งก่อน, `SessionTarget` และนาทีที่ผู้ใช้มี คืน `WarmUpSet`
- `ประเมินฟอร์มการวิ่ง` — รับชุดตัวอย่าง cadence และ pace ตลอด `Session` คืน `FormScore`
- `คำนวณเป้าหมายรายวัน` — รับ `Objective` และประวัติ `Session` คืน `DailyGoal`

### กฎของใบอนุญาตวิ่ง

ตัวที่แย่ที่สุดเป็นคนตัดสิน ไม่เอามาเฉลี่ยกัน เพราะอากาศเย็นสบายไม่ได้ชดเชย PM2.5 ที่พุ่ง

- แดง — อุณหภูมิที่รู้สึกได้ตั้งแต่ 41°C ขึ้นไป หรือ PM2.5 ตั้งแต่ 37.5 µg/m³ ขึ้นไป หรือมีพายุฝนฟ้าคะนอง
- เหลือง — อุณหภูมิที่รู้สึกได้ 35–41°C หรือ PM2.5 25–37.5 µg/m³ หรือ UV ตั้งแต่ 8 ขึ้นไป **หรืออยู่นอกช่วงกลางวัน คือก่อนพระอาทิตย์ขึ้นหรือหลังพระอาทิตย์ตก**
- เขียว — ต่ำกว่าเกณฑ์เหลืองทุกตัว และอยู่ในช่วงกลางวัน คือหลังพระอาทิตย์ขึ้นและก่อนพระอาทิตย์ตก

ความมืดนับเป็นปัจจัยระดับเหลือง ไม่ใช่แดง เพราะวิ่งกลางคืนทำได้ถ้าเลือกที่วิ่งที่มีไฟส่องสว่าง นี่คือปัญหาข้อสามที่โปรเจกต์ตั้งไว้ ระบบจึงต้องเตือน ไม่ใช่ห้าม

ค่า 37.5 µg/m³ คือค่ามาตรฐาน PM2.5 เฉลี่ย 24 ชั่วโมงของประเทศไทย `ClearWindow` คือช่วงชั่วโมงเขียวติดต่อกันที่ยาวที่สุดของวันที่ยังมาไม่ถึง

### แหล่งข้อมูลภายนอก

- **Open-Meteo** — ฟรี ไม่ต้องมี API key ให้อุณหภูมิ อุณหภูมิที่รู้สึกได้ ความชื้น UV ฝน พระอาทิตย์ขึ้นและตก รายชั่วโมง ใช้เป็นแหล่งหลัก
- **Air4Thai** — ฟรี ไม่ต้องมี API key 173 สถานีทั่วประเทศ ใช้แสดงค่า PM2.5 จากสถานีจริงพร้อมชื่อสถานีและระยะห่าง สถานีปราจีนบุรีคือ `77t`
- **OSM Overpass** — ฟรี ไม่ต้องมี API key ใช้ค้นหา `Venue` สดตามตำแหน่งผู้ใช้ ครอบคลุมทุกจังหวัด

สถานี Air4Thai ดับได้จริงและปัจจุบัน `77t` ไม่ส่งค่า PM2.5 ลำดับการถอย คือ ใช้สถานีที่ใกล้ที่สุดที่ยังส่งข้อมูล แล้วถอยไปใช้ค่าจาก Open-Meteo แล้วจึงแสดงว่าไม่มีข้อมูล ต้องแสดงชื่อแหล่งและระยะห่างเสมอ

ตัวเชื่อมทั้งสามตัวแปลงผลลัพธ์เป็นชนิดข้อมูลของโดเมนที่ขอบ ไม่ส่งรูปแบบดิบของ API เข้าไปในโมดูลตัวตัดสินใจ

### ข้อมูล `Venue` สองชั้น

ชั้นครอบคลุมมาจาก Overpass สดตามตำแหน่ง ให้ที่วิ่งทุกจังหวัดแต่ข้อมูลบาง จากการสำรวจจริงพบว่าสี่ในเก้าแห่งรอบปราจีนบุรีไม่มีแม้แต่ชื่อใน OSM และไม่มีแห่งไหนมีข้อมูลสิ่งอำนวยความสะดวกเลย ชั้นละเอียดเป็นไฟล์ที่กรอกเองสำหรับที่วิ่งรอบ มจพ. ปราจีนบุรี ทับข้อมูล Overpass ด้วยการจับคู่พิกัด `Venue` ที่ไม่มีชื่อต้องแสดงเป็นประเภทของมันแทน ไม่ใช่ปล่อยว่าง

### วอร์มอัพ

ดู ADR 0004 — ท่าทุกท่ากำกับขั้น RAMP และ `WarmUpSet` ต้องครบทั้งสี่ขั้นเสมอ ชุดมาตรฐานแปดท่า ตัวเลือกความยาว 5, 10, 15 นาที ปรับด้วยการเพิ่มหรือลดจำนวนท่าในขั้น Mobilise และปรับเวลาต่อท่า ไม่ใช่ตัดขั้นทิ้ง

### ตัวละคร

ดู ADR 0001 — วาดด้วย Skia เป็นโครงกระดูกในโค้ด ข้อต่อคือข้อมูล ท่าคือชุด keyframe ของมุมข้อต่อ แขนขาข้างใกล้ใช้สีอ่อนกว่าข้างไกลเพื่อให้ดูออกว่าข้างไหนเป็นข้างไหน กล้ามเนื้อเป้าหมายเรืองแสง หุ่นเป็นกลางไม่ระบุเพศ

### การวัด cadence

อ่าน accelerometer ผ่าน `expo-sensors` ที่ราว 50 Hz แล้วตรวจจับยอดคลื่นแนวดิ่ง เก็บ cadence เป็นชุดตัวอย่างตลอด `Session` ไม่ใช่ค่าเดียวตอนจบ เพราะ `FormScore` ต้องการรู้ว่ามันตกตอนไหน

### การเก็บข้อมูล

ดู ADR 0003 — `expo-sqlite` และ `AsyncStorage` ในเครื่องทั้งหมด ไม่มี backend หน้าเข้าสู่ระบบเป็นจอจำลอง เก็บแค่ชื่อผู้ใช้ ห้ามเก็บรหัสผ่าน ปุ่ม Google, Apple และ Facebook มีไว้ให้ตรงแบบร่างเท่านั้น

### โครงสร้างการนำทาง

ห้าแท็บ — หน้าหลัก, ที่วิ่ง, วิ่ง, ชุมชน, โปรไฟล์ การตั้ง `SessionTarget` อยู่ในเส้นทางของแท็บวิ่ง ไม่ใช่แท็บของตัวเอง เพราะมันเป็นขั้นตอนหนึ่งของการวิ่งไม่ใช่ปลายทาง แท็บชุมชนรวมปฏิทินงานวิ่งกับหาเพื่อนวิ่ง รวมสิบเจ็ดจอ

### ธีมและตัวอักษร

สีทั้งหมดเป็นตัวแปรกลางตั้งแต่ไฟล์แรก รองรับสว่างและมืดพร้อมปุ่มสลับ ค่าเริ่มต้นเป็นสว่าง ตัวอักษรใช้ Noto Sans Thai ผ่าน `@expo-google-fonts`

## Testing Decisions

### อะไรคือเทสต์ที่ดีในโปรเจกต์นี้

เทสต์ต้องยืนยัน *พฤติกรรมที่มองเห็นจากภายนอก* ของโมดูลตัวตัดสินใจเท่านั้น คือ ใส่ข้อมูลชุดหนึ่งเข้าไปแล้วได้คำตัดสินแบบไหนออกมา ห้ามเทสต์ว่าข้างในคำนวณด้วยขั้นตอนอะไร และไม่ต้อง mock อะไรทั้งสิ้น เพราะฟังก์ชันเหล่านี้ไม่มี dependency ให้ mock อยู่แล้ว ถ้าเทสต์ตัวไหนต้อง mock แปลว่าฟังก์ชันนั้นออกแบบผิดและมี I/O หลุดเข้าไป

### โมดูลที่จะถูกเทสต์

มีที่เดียวคือโมดูลตัวตัดสินใจ ไม่เทสต์จอ ไม่เทสต์แผนที่ ไม่เทสต์ตัวละคร Skia ไม่เทสต์เสียง ไม่เทสต์ตัวเชื่อม API เพราะบั๊กของสิ่งเหล่านั้นเห็นได้ทันทีด้วยตาบนเครื่องจริง ในขณะที่เกณฑ์ตัดสินที่ผิดจะทำให้แอปแนะนำให้คนออกไปวิ่งในสภาพที่ไม่ควรวิ่งโดยที่หน้าจอดูปกติทุกประการ

กรณีที่ต้องครอบคลุมอย่างน้อย

- ใบอนุญาตวิ่ง — ทุกเกณฑ์ที่ทำให้เป็นแดงแยกกันทีละตัว, ทุกเกณฑ์ที่ทำให้เป็นเหลืองแยกกันทีละตัว, กรณีค่าอยู่ตรงเส้นแบ่งพอดี, กรณีที่ตัวหนึ่งดีมากแต่อีกตัวแย่ต้องได้ผลตามตัวที่แย่, กรณีไม่มีค่า PM2.5 เลย
- `ClearWindow` — วันที่ไม่มีชั่วโมงเขียวเลย, วันที่มีช่วงเขียวสองช่วงต้องเลือกช่วงที่ยาวกว่า, ช่วงเขียวที่ผ่านไปแล้วต้องไม่ถูกเลือก, ช่วงเขียวที่ถูกตัดด้วยเวลาพระอาทิตย์ตก
- `WarmUpSet` — ทุกชุดที่คืนออกมาต้องมีท่าครบทั้งสี่ขั้น RAMP ไม่ว่าจะเลือก 5, 10 หรือ 15 นาที, วันที่ร้อนต้องไม่มีท่ากระโดด, `FormScore` ที่บอกว่า cadence ตกต้องทำให้มีท่าน่องและหน้าแข้ง, ผลรวมเวลาต้องไม่เกินเวลาที่ผู้ใช้มี
- `FormScore` — cadence ที่คงที่ตลอดต้องไม่ถูกตัดสินว่าฟอร์มเสีย, cadence ที่ตกช่วงท้ายต้องถูกจับได้, `Session` ที่สั้นเกินกว่าจะสรุปอะไรได้ต้องบอกว่าข้อมูลไม่พอแทนที่จะเดา
- `DailyGoal` — `Objective` แต่ละแบบให้ผลต่างกันจริง, มาราธอนต้องไม่เพิ่มเกินสิบเปอร์เซ็นต์ต่อสัปดาห์, ผู้ใช้ที่ไม่มีประวัติเลยต้องได้ค่าเริ่มต้นที่ปลอดภัย

### Prior art

ไม่มี ยังไม่เคยมีเทสต์ในโปรเจกต์นี้และยังไม่มี test framework ติดตั้ง เนื่องจากโมดูลตัวตัดสินใจไม่มี import จาก React Native เลย ให้ใช้ **vitest** ซึ่งไม่ต้องตั้งค่า transform ของ React Native แทนที่จะใช้ `jest-expo` ที่หนักกว่ามาก เทสต์ชุดแรกที่เขียนจะกลายเป็น prior art ให้ชุดถัดไป

## Out of Scope

- **Development build และการลงสโตร์** ทั้งหมด รวมถึง EAS Build, keystore, Google Maps API key และการรีวิวของ Google Play
- **GPS ที่ทำงานต่อเมื่อปิดหน้าจอ** ผู้ใช้ต้องเปิดหน้าจอค้างไว้ระหว่างวิ่ง
- **การเชื่อมต่อนาฬิกา สายคาดอก Health Connect และ HealthKit** ค่า Heart Rate เป็นข้อมูลจำลองที่มีป้ายกำกับ
- **Backend, ฐานข้อมูลบนคลาวด์ และการยืนยันตัวตนจริง** รวมถึง OAuth ของ Google, Apple และ Facebook ที่มีแค่ปุ่ม
- **การซิงก์ข้อมูลข้ามเครื่อง**
- **ปฏิทินงานวิ่งไทย, หาเพื่อนวิ่ง และการสร้าง `Route` วงกลมตามระยะที่ขอ** — สร้างเป็นจอที่กดดูได้แต่ใช้ข้อมูลจำลองทั้งหมด ไม่มีตรรกะจริงอยู่เบื้องหลัง
- **การยืนยันตัวตนสำหรับหาเพื่อนวิ่ง**
- **ข้อมูลไฟส่องสว่างของถนนจริง** ฟีเจอร์เรื่องแสงทำได้แค่การเตือนก่อนพระอาทิตย์ตกและป้ายไฟส่องสว่างของ `Venue` ที่กรอกเอง
- **ภาษาอังกฤษ** เขียนผ่านไฟล์ i18n ตั้งแต่ต้นแต่มีแค่ภาษาไทย
- **เว็บ** สนใจเฉพาะ Android และ iOS ผ่าน Expo Go
- **การวัด ground contact time และความสมมาตรซ้ายขวา** ต้องใช้เซ็นเซอร์ที่รองเท้าหรือแม่นยำกว่าที่มือถือในกระเป๋าให้ได้
- **เทสต์ของ UI, แผนที่, ตัวละคร และตัวเชื่อม API**

## Further Notes

โปรเจกต์นี้เป็น prototype สำหรับนำเสนอในวิชา Design Thinking มีเวลาสิบสี่วัน คนเขียนโค้ดคนเดียว แผนรายวันอยู่ที่ `docs/plan-14-days.md` และคำศัพท์ทั้งหมดอยู่ที่ `CONTEXT.md`

สิ่งที่ทำให้ spec นี้ผูกกันเป็นเรื่องเดียว คือ ทุกฟีเจอร์สืบกลับไปหาปัญหาสามข้อที่ทีมตั้งไว้ในเอกสารนำเสนอตั้งแต่ต้น ได้แก่ สภาพอากาศ การบาดเจ็บที่น่อง และแสงสว่างไม่เพียงพอ ถ้าต้องตัดอะไรออกเพราะเวลาไม่พอ ให้ตัดจากสิ่งที่ไม่ได้สืบกลับไปหาสามข้อนี้ก่อนเสมอ

ลำดับความเสี่ยงจากมากไปน้อย คือ ตัวละคร Skia เพราะเป็นงานที่ต้องปรับจนตาดูแล้วสวยไม่ใช่งานที่ทำงานแล้วจบ, หน้าวิ่งจริงเพราะพึ่ง GPS และเซ็นเซอร์ที่ทดสอบได้บนเครื่องจริงเท่านั้น, แล้วจึงเป็นจอที่เหลือซึ่งตัดออกได้โดยไม่กระทบเรื่องเล่าหลัก
