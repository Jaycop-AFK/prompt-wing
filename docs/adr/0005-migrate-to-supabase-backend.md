# ย้ายไปใช้ Supabase เป็น backend จริง แทนที่ ADR 0003

ยกเลิก [ADR 0003](0003-no-backend-all-data-on-device.md) ทั้งหมด พร้อมวิ่งมี backend จริงแล้ว
ผ่าน Supabase (Postgres + Auth) และ Mapbox (เส้นทางวิ่งตามถนนจริง) หลังจากงานนำเสนอเดิมที่ ADR 0003
พูดถึงจบไปแล้ว

## เหตุผล

ผู้ใช้ (ทีมงาน) ตัดสินใจเองว่าอยากให้ระบบ "CRUD ได้จริง" ทั้งระบบ ไม่ใช่ข้อมูลจำลองหรือเก็บแค่ในเครื่อง
อีกต่อไป โดยรับทราบและยอมรับผลที่ตามมาอย่างชัดเจนแล้วว่า **แอปจะกลับมาต้องมีอินเทอร์เน็ตตลอดเวลา**
ซึ่งเป็นความเสี่ยงเดียวกับที่ ADR 0003 ตั้งใจเลี่ยงไว้ตอนแรกเป๊ะ ยอมรับความเสี่ยงนี้ได้เพราะงานนำเสนอ
ที่ ADR 0003 กังวลถึงจบไปแล้ว หรือมั่นใจเรื่องเน็ตในสถานที่นำเสนอจริง

## สิ่งที่เปลี่ยนจริง

- **เข้าสู่ระบบ**: Supabase Auth จริงด้วยอีเมล+รหัสผ่าน (`hooks/use-auth.tsx`) แทนระบบจำลองที่เก็บ
  แค่ชื่อผู้ใช้ ปุ่ม Google/Apple/Facebook **ยังคงเป็นภาพจำลอง** ตามที่ตัดสินใจไว้ตอนย้าย เพราะต้องไป
  สมัคร OAuth app กับผู้ให้บริการแต่ละเจ้าเองก่อน ซึ่งเป็นงานนอกเหนือจากที่ทำได้ในเซสชันนี้
- **ประวัติการวิ่ง โปรไฟล์ ที่บันทึกไว้**: ย้ายจาก `expo-sqlite`/`AsyncStorage` ไปเก็บบน Postgres
  จริงผ่าน Supabase (`storage/session-storage.ts`, `storage/profile-storage.ts`,
  `storage/venue-favorites.ts`) ผูกกับผู้ใช้จริงด้วย Row Level Security ทุกตาราง (ดู
  `supabase/schema.sql`)
- **ปฏิทินงานวิ่ง**: ตารางจริง (`race_events`) อ่านได้ทุกคน แก้ไขผ่าน Supabase Table Editor
- **หาเพื่อนวิ่ง**: จับคู่จากโปรไฟล์ผู้ใช้จริงที่เปิด `visible_to_others` ไว้ เรียงตาม pace ใกล้เคียง
  ของตัวเอง ป้าย "ยืนยันแล้ว" อิงจากสถานะยืนยันอีเมลจริงของ Supabase Auth (ไม่ใช่การยืนยันตัวตน
  แบบเต็มรูปแบบ ซึ่งยังอยู่นอกขอบเขตเหมือนเดิม)
- **เส้นทางวงกลม**: คำนวณจุดคร่าว ๆ ด้วยเรขาคณิตเดิม (`services/route-generator.ts`) แล้วส่งให้
  Mapbox Optimization API ต่อเป็นเส้นทางจริงตามถนน/ทางเดิน (`services/mapbox-routing.ts`) ระยะทาง
  ที่ได้จริงจะไม่ตรงเป๊ะกับที่ขอ เพราะต้องเดินตามถนนจริง

## สิ่งที่ยังไม่เปลี่ยน ตั้งใจ

- **ชีพจร (Heart Rate)** ยังเป็นข้อมูลจำลองเหมือนเดิม เพราะเป็นข้อจำกัดของฮาร์ดแวร์ ไม่ใช่ข้อจำกัด
  ของสถาปัตยกรรมข้อมูล มือถือเปล่าวัดชีพจรจริงไม่ได้ไม่ว่าจะมี backend หรือไม่ก็ตาม ต้องมีอุปกรณ์
  เสริม (สายรัดอกหรือนาฬิกา) ซึ่งเป็นฟีเจอร์ใหม่ทั้งหมด (การจับคู่ Bluetooth) ไม่ใช่ส่วนหนึ่งของการ
  ย้าย backend ครั้งนี้
- **การแจ้งเตือนในหน้าเพิ่มเติม** ยังเป็นสวิตช์ที่ไม่มีผลจริง เพราะไม่มีฟีเจอร์แจ้งเตือนใด ๆ ในแอปเลย
  ให้ backend ไปเชื่อมด้วย (ไม่มีตัวส่งแจ้งเตือน ไม่มีตารางเวลาเตือนวิ่ง) ทำสวิตช์ให้ขอสิทธิ์ระบบจริง
  โดยไม่มีฟีเจอร์อะไรอยู่เบื้องหลังเลยจะเป็นเปลือกว่างเปล่า ไม่ใช่การอัปเกรดของจริง
- **หน่วยการวัด (กม./ไมล์)** และ **ความนิยมของที่วิ่ง** ยังไม่ได้ทำเป็นของจริงในรอบนี้ เพราะเป็น
  ฟีเจอร์ใหม่คนละขอบเขตจากการย้าย backend (หน่วยการวัดต้องแก้ตัวจัดรูปแบบตัวเลขทั่วทั้งแอป ความนิยม
  ต้องสร้างระบบให้คะแนนที่วิ่งใหม่ทั้งระบบ) ยังไม่ได้ถามหรือยืนยันขอบเขตนี้กับผู้ใช้ในรอบนี้

## ข้อควรระวังที่ยังใช้ได้เหมือนเดิม

ห้ามเก็บรหัสผ่านเป็น plain text หรือ hash เองที่ฝั่งแอปเด็ดขาด ปล่อยให้ Supabase Auth จัดการทั้งหมด
(แอปแค่ส่งรหัสผ่านผ่าน TLS ไปให้ Supabase ตรง ๆ ไม่เก็บไว้เองแม้แต่ในหน่วยความจำนานเกินความจำเป็น)

`EXPO_PUBLIC_SUPABASE_ANON_KEY` และ `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` ที่ฝังในแอปเป็น key สาธารณะ
ที่ตั้งใจให้ฝังในไคลเอนต์ได้ ตัวป้องกันข้อมูลจริงคือ Row Level Security ของ Supabase (ดู
`supabase/schema.sql`) ไม่ใช่การซ่อน key เหล่านี้
